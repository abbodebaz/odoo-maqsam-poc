# Configuration Guide

## WATI connection

Open **WhatsApp / WATI → Settings** in Odoo and configure the WATI API values provided by the customer's WATI account.

Do not copy credentials from another company or from a staging environment. Each customer should use its own WATI credentials.

After entering the connection details, use the connection test before proceeding.

## Webhook

Copy the webhook URL generated by the connector from Odoo Settings and register it in WATI.

Enable the WATI webhook events required by the customer's use of the connector, including message and template lifecycle/status events used by the installed features.

After saving the webhook in WATI, send a test inbound WhatsApp message and confirm it is received in Odoo.

## Access control

Configure WATI roles/groups in Odoo according to the customer's operating model. Use least privilege: users should receive only the WATI capabilities they need.

Typical separation is:

- WATI users/agents: day-to-day conversations and sending.
- WATI administrators: templates, automation, monitoring and connector administration.
- Odoo system administrators: full technical administration.

## Inbox

The Settings page includes controls for Inbox-related features. Enable only the customer-facing tools the company wants to expose to users.

## Smart WhatsApp button and timeline

Use the Smart Button settings to select the Odoo application/model/form where WhatsApp actions should appear, and map the phone/customer source for that model.

The universal timeline can correlate by linked customer and/or normalized WhatsApp phone number, depending on the source record.

## Templates

Templates are created/synchronized through the Template Center. Approval remains subject to WATI/Meta rules and the customer's WATI account.

## Automation

Configure automations only after the target model, trigger, recipient and template/message behavior have been validated in the customer's database.

## Security notes

- Never store or email production API tokens in plain-text documentation.
- Use the customer's secret-management practice for infrastructure credentials.
- Restrict Odoo technical administration to trusted administrators.
- Back up the database before upgrades.
